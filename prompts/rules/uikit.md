UI KIT
- The project has a UI kit. styles/kit/tokens.css holds the colours and sizes (the project's own: restyle there). styles/kit/kit.css holds the components, and the helper program writes it: after each change it has the rules of every kit class your pages use, so use a class and its CSS follows; never edit kit.css. Link tokens.css, then kit.css, before your own styles.
- The kit comes first, for every piece of interface, in this order: a kit component or class (the list below); a kit script part (tables with sorting and pages, charts, icons, file readers); kit parts combined. Only for what the kit does not have, write your own markup and CSS, built on the tokens, and say in one line which part was missing. Never build your own version of something the kit has (buttons, tables, charts, icons, dialogs, tabs, notices, empty states).
- Where everything is: the whole kit is in .streamhub/ui-kit/ (read-only, the kit's catalogue). The project context lists its parts with their lines in .streamhub/ui-kit/kit-examples.html: read that part (read PATH:START-END) before you use it, and copy its markup. A search for a kit class (grep) finds its example and its CSS there too. Kit scripts and React parts come the same way: refer to styles/kit/NAME (a script tag, or an import from styles/kit/react/) and the helper program adds that file, with what it needs, after your change.
- Colours: use the working tokens (--kit-accent, --kit-text, --kit-chart-1...); they already pick readable colours for light and dark. With the blue palette the named colours are --kit-palette-* (each with -1 lighter and -2 darker variations): blue is the primary accent, light blue the secondary one for decoration and highlights. The only gradient is var(--kit-gradient) (kit-gradient, kit-band), for decorative areas, never behind small text.
- Restyle through the tokens (var(--kit-...)); do not hard-code colours, sizes or shadows. Your own CSS uses the same tokens. Keep text readable in light and dark (WCAG AA: 4.5:1 for text, 3:1 for large text and for the edges of fields and buttons); the helper program measures it.
- Page header: <header class="kit-header kit-header--band"><div class="kit-container"><h1 class="kit-header__title">TITLE</h1> ... </div></header>, the gradient bar at the top of every app and dashboard page (links and text in it follow the band's colour). A plain kit-header only for a page shown inside another page. A light/dark switch is <button class="kit-btn kit-btn--ghost kit-btn--icon" type="button" data-kit-theme><span data-kit-icon="moon" aria-hidden="true"></span></button> (kit.js: follows the computer until clicked, keeps the choice, sets its icon and label); never write your own.
- Components: kit-header kit-header--band kit-header__title; kit-btn (--primary --ghost --danger --sm); kit-field kit-label kit-input kit-select kit-textarea kit-help kit-error-text kit-check kit-form (is-active on a kit-select or kit-input while it filters); kit-toolbar kit-toolbar__spacer kit-segmented; kit-table-wrap kit-table-wrap--scroll kit-table kit-num; kit-badge (--accent --ok --warn --error); kit-tabs kit-tab; kit-split kit-nav kit-nav__item kit-panel kit-panel--sticky kit-panel__head kit-panel__title; kit-figures kit-figure__label kit-figure__value kit-figure__note kit-figure__bar (a share under a figure: kit-progress kit-figure__bar with kit-progress--ok, --warn or --error, and kit-progress__bar with its width); kit-progress kit-progress__bar (give the kit-progress role="progressbar" and aria-valuenow="PERCENT": kit.js fills the bar to it; without kit.js set the bar's style="width: PERCENT%", the same number the row shows); kit-chips kit-chip (one per active filter, a click removes it); kit-notice (--ok --warn --error) kit-notice__title; kit-empty kit-empty__title (every list, table and chart has one); kit-dialog kit-dialog__actions; kit-section kit-stack kit-row kit-row--between kit-grid kit-grid--charts kit-grid__wide kit-divider; kit-h1 kit-h2 kit-h3 kit-prose kit-muted kit-small kit-mono kit-link kit-kbd kit-spinner; kit-page and kit-container on the page itself.
- Tables (styles/kit/kit.js after the markup): every kit-table gets data-kit-sort, so each column sorts; a kit-table with data-kit-sort (every header sorts: th.kit-num as numbers, data-sort="VALUE" on a cell for dates or formatted numbers; kit:sort) and data-kit-pages="N" (a kit-pager under the table; kit:page), which sort and page again when your code writes the rows again; for more than about a thousand rows add data-kit-rows="external" and data-key="FIELD" on each th: the kit draws the sort buttons and the pager, your code keeps the rows in its data, sorts them on kit:sort (detail.key, detail.ascending), writes only the rows from detail.start to detail.end (kit:sort and kit:page) and sets data-kit-total="ROWS" (and data-kit-page="1" after a filter change) on the table; put a long table in kit-table-wrap kit-table-wrap--scroll so its header row stays in view (see the long table section of the examples).
- Interactive parts (need styles/kit/kit.js after the markup; they report through DOM events): kit-btn--hold with data-kit-hold (event kit:hold); kit-search with data-kit-search, kit-search__list, kit-search__item, kit-search__meta (kit:pick); kit-drop with data-kit-drop, kit-drop__title, kit-drop__files, kit-progress, kit-progress__bar (kit:files); kit-tabs--animated and kit-segmented--animated (kit:select); kit-loading with kit-loading__text; kit-composer with kit-composer__actions. In a React project use styles/kit/react/ instead: HoldButton, SearchBox, DropZone, Tabs, Segmented, Loading, Composer, CommandButton.
- Icons (Lucide, any icon name): <span data-kit-icon="NAME" aria-hidden="true"></span>, loaded by styles/kit/kit-icons.js (include it after the markup); the helper program adds the icons you use. A button with only an icon needs aria-label (kit-btn kit-btn--icon). React: Icon from styles/kit/react/. Never an emoji as an icon.
- Charts: styles/kit/kit-charts.js draws them on the kit's colours (no chart library). Write <div class="kit-chart" data-kit-chart="bar|line|area|ring|gauge|heatmap|sparkline|barlist" data-kit-data='JSON' aria-label="WHAT IT SHOWS"></div> (see the charts section of .streamhub/ui-kit/kit-examples.html), or call KitCharts.bar(element, data) from code; React: Chart from styles/kit/react/. Options: bar "horizontal": true (bars to the right), "stacked": true (one bar per label, series on top of each other); a bar series with "type": "line" (and "axis": "right" for its own scale) draws a line over the bars, e.g. a running total next to the counts per date; ring "legend": "values" (a list with each value and its share); barlist (label, bar, value per row): "limit": N adds Show all, "share": true shows each value with its share ("total": N for the share of something other than the sum), "base": "first" makes a funnel (each step against the first). Bar, line and area: "targets": [{ "value": N, "label": "Goal" }] draws a dashed target line; bar "stacked": "percent" makes every bar 100% with the parts as shares.
- Your choice, the kit's look: which data to show, and as what, is yours to decide; the kit sets no limits on it (vertical, horizontal or stacked bars, lines, areas, rings, gauges, heatmaps, bar lists, funnels, tables, lists, key figures: whatever fits the data and the question). Whatever you choose must look like the kit: draw it with the kit part for that form and its options (the charts above, kit-table, kit-figures ...), never a version of your own; only a form the kit has no part for is drawn by the page, on the tokens and the kit's chart classes (below). Colours that mean something (done, waiting, failed) go on the items: "color": "ok", "warn", "error", "muted" or "accent" on a barlist or ring item (or "chart-1" ... "chart-6"), always with a label that says the same; never a colour of your own.
- Chart colours: whenever a chart shows more than one colour (series, stacked parts, ring or donut slices, categories, legend entries), the colours are var(--kit-chart-1) to var(--kit-chart-6) in that order, the project's colour preset; never shades of one colour, a generated palette or colours of your own. The kit's charts do this by themselves; a colour by meaning (ok, warn, error) is the only exception.
- Anything a page draws itself (SVG, canvas, bars made of elements, a legend) takes its colours from var(--kit-chart-1) to var(--kit-chart-6) in that order, so the same series has the same colour in every chart, and uses the kit's chart classes: kit-chart__legend, kit-chart__swatch, kit-chart__tip, kit-chart__label, kit-chart__line, kit-chart__base. In canvas code, or anything else that needs colour values instead of var(), take KitCharts.palette(N) (the N preset colours in order; read them again on kit:theme), or getComputedStyle(document.documentElement).getPropertyValue("--kit-chart-1"). Bars drawn against a chart axis (bar and column charts) are flat at the axis; only the far end may be rounded. Bars in a track (progress and status bars, bar lists, a share bar in a table row: kit-progress, kit-barlist) are round at both ends (canvas roundRect with [r, r, 0, 0], not one radius). No chart library (they bring their own colours) and no colours of your own.
- Dashboards: what a dashboard shows is your choice. The parts you use look as in the dashboard section of .streamhub/ui-kit/kit-examples.html: the band header; a filter bar as kit-panel kit-panel--sticky with kit-toolbar and kit-chips; key figures as kit-figures; charts in kit-grid kit-grid--charts, one chart per kit-panel with a title that says what to see (kit-grid__wide for a chart across the row); charts that filter the page use "selectable" and kit:select as there.
- Dashboard parts (styles/kit/kit.js after the markup; see the dashboard parts section of the examples): details of a row or an edit in place in a side panel, <dialog class="kit-drawer" id="ID"> with kit-drawer__head, kit-drawer__title, kit-drawer__body and kit-drawer__actions, opened by a button with data-kit-open="ID" and closed by a button with data-kit-close (Escape and a click beside it close it too; kit:open, kit:close; data-kit-open opens a kit-dialog the same way); a short confirmation after an action with KitUI.toast("Saved", { tone: "ok" }) (warn, error); an explanation of a figure or column with <button class="kit-tip" type="button" aria-label="QUESTION" data-kit-tip="ANSWER"></button>; placeholders while data loads with kit-skeleton (--text --figure --chart --row) in a box with aria-busy="true"; a change on a key figure with <span class="kit-trend kit-trend--up kit-trend--good">+4.2% vs last month</span> (--down, --flat; --good or --bad for what it means) and a small trend under it with a sparkline in kit-figure__spark; a filter for several values with <select multiple class="kit-select" data-kit-multi aria-label="NAME"> (nothing ticked means all; change and kit:multi with detail.values); a period filter with <div class="kit-range" data-kit-range data-value="30d" aria-label="Period"></div> (data-presets="7d,30d,week,month,quarter,year,all,custom"; kit:range with detail.from and detail.to as yyyy-mm-dd, both included, empty for all; KitUI.range(PRESET) gives the same dates); a search box over a table with <input class="kit-input kit-table-search" type="search" data-kit-filter="TABLE-ID" aria-label="Search the table"> (rows without the words hide, sorting and paging go on; kit:filter; with data-kit-rows="external" filter your rows on kit:filter); a totals row in <tfoot class="kit-table__total"> (never sorted); kit-table--sticky-first keeps the first column in view in a wide table; when the data is from with <span class="kit-stamp" data-kit-stamp="ISO DATE"></span>, or data-kit-stamp-of="GLOBAL" for a data block the helper program fills (it gives the source file's time), or KitUI.stamp(element, date). In a React project use styles/kit/react/ instead: Drawer, Toaster and toast, Tip, MultiSelect, PeriodFilter and periodOf, Stamp.
- More components (styles/kit/kit.js after the markup; see the more components section of the examples): an on/off setting with <label class="kit-switch"><input type="checkbox" role="switch"><span class="kit-switch__track" aria-hidden="true"></span>LABEL</label>; actions behind one button with a kit-menu (a button with data-kit-menu aria-haspopup="menu" aria-expanded="false", then <div class="kit-menu__list" role="menu" hidden> with kit-menu__head, kit-menu__item buttons role="menuitem" with data-value, kit-menu__item--danger, kit-menu__sep; kit:menu with detail.value); switching views with a kit-iconbar (role="toolbar", data-kit-iconbar="single" or "multiple", kit-iconbar__item buttons with aria-pressed, an icon and a kit-iconbar__label; kit:select); people with <span class="kit-avatar" data-kit-avatar="NAME"></span> (initials and a colour per name; kit-avatar--sm, --lg) and a kit-avatars group ending in <span class="kit-avatars__more">+N</span>; where the page is with kit-breadcrumbs; the steps of a form with a kit-stepper (kit-stepper__step, is-done, aria-current="step"); details with <dl class="kit-dl">; what happened with a kit-timeline (kit-timeline__item with --ok --warn --error --accent, kit-timeline__time); sections that open with <details class="kit-accordion"> (kit-accordion__body; the same name keeps one open); a value with <input class="kit-slider" type="range">, two values with <div class="kit-slider-range" data-kit-slider-range data-min data-max data-from data-to aria-label="NAME"></div> (kit:slide); tags with <div class="kit-tags" data-kit-tags data-name="FIELD" aria-label="Add a tag"></div> (kit:tags); work in columns with a kit-board (kit-board__column, kit-board__title, <ul class="kit-board__list" data-kit-board="COLUMN">, kit-board__card with data-id; drag or Alt with an arrow key; kit:move with detail.id, from, to, index); a month with <div class="kit-calendar" data-kit-calendar data-month="YYYY-MM" aria-label="NAME"></div> and KitUI.calendar(element, { month, events: [{ date, title, tone }] }) (kit:day, kit:month); cards of different sizes in a kit-bento (kit-bento__item--wide, --tall); changing loading text with data-kit-cycle="FIRST|SECOND" on a kit-loading__text; a finished action with a kit-success and its kit-success__check. On a phone the side panel opens as a sheet from the bottom by itself. In a React project use styles/kit/react/ instead: Switch, Menu, IconBar, Avatar and AvatarGroup, SliderRange, TagInput, Board, Calendar.
- Printing: dashboards and reports print cleanly by themselves (screen-only parts such as buttons, filters and toolbars stay off paper, panels and charts are not split, the light theme is used). A print button is <button class="kit-btn" type="button" data-kit-print>Print</button>; kit-no-print keeps another part off paper, kit-print-only shows a part only on paper (a title with the filters chosen, the date).
- SQL in the page: to group, join or filter data with SQL, load <script src="styles/kit/vendor/sqljs/sql-asm.js"></script> and <script src="styles/kit/kit-sql.js"></script> (in that order), then KitSql.open({ sales: rows, people: rows2 }).then(function (db) { var rows = db.query("SELECT region, SUM(amount) AS total FROM sales GROUP BY region"); }): each list of row objects becomes a table; db.query(sql, params) gives row objects. It works from disk too. Use it where SQL is clearer than JavaScript loops; DataTools covers simple sums and groups.
- Python in the page: <script src="styles/kit/kit-python.js"></script>, then KitPython.run(CODE, { data: { sales: rows } }).then(function (r) { r.result; r.output; }) runs Python with its standard library (statistics, csv, json, datetime; no pandas or numpy) on the page's data; the value of the last line comes back as r.result. It works only when the page is served (Open app), so say so to the person, and show a kit-notice when it is opened from disk (location.protocol === "file:"). The first run takes a few seconds: show kit-loading meanwhile.
- Export: a button that saves the rows shown (the filtered rows) as CSV uses styles/kit/kit-data.js: KitData.download("NAME.csv", KitData.toCsv(rows, [{ key, label }, ...])). Never write your own CSV writer or download code.
- Reading files a person picks or drops (in the page, nothing uploaded): styles/kit/kit-data.js (include it before your script). KitData.readFile(file) returns a promise of { kind: "table", sheets, rows } for CSV, TSV and Excel (values typed: numbers, true/false, dates as yyyy-MM-dd text, empty cells null), { kind: "json", data }, { kind: "document", blocks, text } for Word, { kind: "slides", slides, text } for PowerPoint, { kind: "pdf", pages, text }; use KitData.accept on the file input. Never write your own CSV, Excel or Office parser. React: useFileData from styles/kit/react/. PDF: include styles/kit/vendor/pdfjs/pdf.min.js and pdf.worker.min.js before kit-data.js.
- Page grid: put the page in kit-container (header contents too: kit-header > kit-container), so everything shares one left and right edge (--kit-page-width, --kit-page-pad).
- Type is Arial (--kit-font, set on kit-page: no font-family of your own); sizes from --kit-text-xs, -sm, -md, -lg, -xl (or kit-h1, kit-h2, kit-h3, kit-small), corners var(--kit-radius) or var(--kit-radius-lg), shadows var(--kit-shadow). Headings and labels in sentence case, never all capitals.
- Every table, list and chart has an empty state (a kit-empty block; in a table a <tr data-kit-empty> row), and data that loads shows kit-loading or kit-spinner while it loads and a kit-notice--error when it fails. Tables, buttons, fields and dialogs always carry their kit class.
- Looks the person asked for (styles marked /* Look asked for: ... */ or <!-- Look asked for: ... -->) stay as they are: never change them back to the kit's look, and use the kit for everything else.
- Avoid: gradient text, thick coloured side stripes on boxes, decorative blur or glass effects, big hero numbers with tiny labels, rows of identical cards, panels inside panels.
