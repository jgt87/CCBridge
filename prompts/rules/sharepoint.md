SHAREPOINT HTML PAGE (the user opens this page as an HTML page in SharePoint, which shows it in a sandbox; anything it blocks fails silently, as a blank or half-drawn page):
- One .html file of at most 10 MB, saved as UTF-8. Every script in <script> blocks and every style in <style> blocks of that file: no <script src>, <link> stylesheets, module imports, workers or CDNs. The helper program puts the UI kit and the data inside the page through its one-file blocks.
- Images only as data: addresses (base64) or inline SVG and canvas; fonts only embedded as data: or a system font stack. No video, audio, iframes, objects or embeds (Power BI, Forms and video players do not load).
- No network at all: fetch, XMLHttpRequest, WebSocket and the like are blocked, also to SharePoint and Microsoft Graph. Data is either written into the page (the helper program's data block) or read from SharePoint files and lists through LiveData: a <script type="application/json" class="ka-livedata-manifest"> block holding a JSON array of { "spItemUrl": "https://HOST/_api/v2.0/drives/DRIVE-ID/items/ITEM-ID", "fileName": "NAME.csv" } (or a list: "kind": "list", "spItemUrl": "list:SITE-URL/LIST-ID", "webUrl", "listId"), at most 32 items. SharePoint reads them with the viewer's access before the page's scripts run and sets window.__LD_RESULTS__ keyed by spItemUrl: each has format (csv, text, xlsx-sheets with each sheet as <sheet name="NAME">CSV</sheet>, or rows as a JSON string of { headers, rows }) and content, or error and errorCode when it could not be read. Parse it yourself, show an error or empty state for a missing item, and put values in with textContent, never innerHTML. Never invent drive or item ids: ask the user for the file or list, or leave the address for them to fill in.
- No browser storage (localStorage, sessionStorage, cookies, indexedDB): keep a choice that should survive a refresh in location.hash. history.pushState and replaceState throw. alert, confirm and prompt do nothing: show messages in the page. Forms cannot submit and nothing is written back to SharePoint: the page only shows and filters.
- Links open in a new tab, and only to SharePoint in the same organisation or sites the organisation allows; a #anchor stays in the page. No window.open, location changes or javascript: links. To refresh the data: parent.postMessage({ type: 'ka-html-viewer-refresh' }, '*') (at most once every 5 seconds; it reloads the page).
- The page does not take the site's theme or dark mode: it looks the same everywhere.
