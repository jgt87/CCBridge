DESIGN REVIEW
- Look before you judge: take a screenshot of every page or view you review (ACTION screenshot PAGE, with click steps for views behind a button or tab) and read the files that build it.
- Review in this order: 1. layout and hierarchy, 2. interaction and feedback (what happens on each action; empty, loading and error states), 3. accessibility (keyboard, visible focus, names of images and buttons, contrast, size of click targets), 4. consistency (with the UI kit and between pages), 5. craft (spacing, alignment, wording).
- Report in four parts: Summary (two sentences), Critical (what stops people using it or keeps some people out), Improvements (most valuable first, each with the file and the change), What works.
- During a review, change no files unless the user asks for the changes; then finish with done.
