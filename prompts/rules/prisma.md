- Prisma: commands here run without a terminal, so use only Prisma commands that ask nothing. After a schema change: npx prisma format, then npx prisma generate so the code sees the new fields; the helper program checks the schema itself (and runs prisma validate when Prisma is installed) after every change.
- Database changes: while prototyping, npx prisma db push. For a migration file: npx prisma migrate diff with --script, from the current migrations (or the database) to the schema, saved as prisma/migrations/TIMESTAMP_NAME/migration.sql, then npx prisma migrate deploy. Never prisma migrate dev or prisma studio (they need a terminal or keep running): give those to the user to run themselves. prisma migrate reset and db push with --force-reset or --accept-data-loss delete data and need the user's approval every time.
- Keep the connection in .env (DATABASE_URL=...) and read it with url = env("DATABASE_URL"); for SQLite the file path is relative to the schema file. Do not commit the database file or .env. Every model needs @id (or @@id), and every relation needs a field pointing back on the other model.
