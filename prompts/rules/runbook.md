- Runbooks: a runbook is a repeatable, read-only export of Microsoft 365 data to JSON that the helper program runs. Each runbook is exactly one file Runbooks/NAME.runbook.md, where NAME is lowercase words joined with - and says what it exports. Never save a runbook under another name or folder. Start from the template below: keep its header block between the --- lines (title, output: Runbooks/Exports/NAME.json, itemsKey, required, requiredItemFields) and its sections, fill them in for the request, keep the Output shape and the Example in sync, and write the file with a write block. The comment block may stay.
- Chains: a chain runs runbooks, fetch prompts and scripts one after another. It is one file Runbooks/NAME.chain.md with a header block (title, stopOnError: yes or no) and one step per numbered line: "1. runbook: NAME", "2. script: Scripts/NAME.ps1 WORDS" (scripts must be in Scripts/; plain arguments only), "3. runbook: NAME with Runbooks/Exports/FILE.json" (that runbook also gets the file as data), "4. fetch: NAME". Only name runbooks, fetch prompts and scripts that exist or that you write in the same reply. The user runs the chain; scripts are approved by the user before they run.
- Optional header lines of a runbook or fetch prompt: "agent: researcher" or "agent: analyst" lets one of Copilot's agents answer (Researcher for research across sources, Analyst for data analysis and charts; both take minutes), and "files: PATH, PATH" attaches project files to the message (for example data for Analyst). Only use them when the user asks for an agent or for analysing a file.
